# File Upload Feature — Test Cases

Below is a comprehensive test suite for a file upload feature, covering functional behavior, validation, security, error handling, and user experience.

Assumptions: The feature supports single and multiple file uploads, enforces file type and size restrictions, and uploads files to a backend server.

| ------- | ------------------------------------------------------ | ------------------------------------------------------ |
| FU-001  | Upload a valid file                                    | File uploads successfully                              |
| FU-002  | Upload multiple valid files                            | All files upload successfully                          |
| FU-003  | Upload a file using drag and drop                      | File uploads successfully                              |
| FU-004  | Select a file using the file picker                    | Selected file appears in upload interface              |
| FU-005  | Upload a file with spaces in its name                  | File uploads successfully                              |

## 5. Example automated tests — Playwright + TypeScript

The following example assumes a file input with `data-testid="file-upload"`, an Upload button, and status messages.

```

import { test, expect } from "@playwright/test";

test.describe("File Upload Feature", () => {
  test.beforeEach(async ({ page }) => {
    await page.goto("/upload");
  });

  test("FU-001: upload a valid file", async ({ page }) => {
    await page.getByTestId("file-upload").setInputFiles({
      name: "sample.pdf",
      mimeType: "application/pdf",
      buffer: Buffer.from("%PDF-1.4\nTest document")
    });

    await page.getByRole("button", { name: "Upload" }).click();

    await expect(
      page.getByText("Upload successful")
    ).toBeVisible();
  });

  test("FU-012: reject unsupported file type", async ({ page }) => {
    await page.getByTestId("file-upload").setInputFiles({
      name: "script.exe",
      mimeType: "application/octet-stream",
      buffer: Buffer.from("invalid executable")
    });

    await expect(
      page.getByText("Unsupported file type")
    ).toBeVisible();
  });

  test("FU-015: reject oversized file", async ({ page }) => {
    const oversizedFile = Buffer.alloc(
      11 * 1024 * 1024
    );

    await page.getByTestId("file-upload").setInputFiles({
      name: "large.pdf",
      mimeType: "application/pdf",
      buffer: oversizedFile
    });

    await expect(
      page.getByText("File size exceeds the limit")
    ).toBeVisible();
  });

  test("FU-009: remove selected file", async ({ page }) => {
    await page.getByTestId("file-upload").setInputFiles({
      name: "sample.txt",
      mimeType: "text/plain",
      buffer: Buffer.from("Test content")
    });

    await page.getByRole("button", { name: "Remove" }).click();

    await expect(
      page.getByText("sample.txt")
    ).not.toBeVisible();
  });

  test("FU-031: handle server error", async ({ page }) => {
    await page.route("**/api/upload", async route => {
      await route.fulfill({
        status: 500,
        body: JSON.stringify({
          error: "Internal server error"
        }),
        contentType: "application/json"
      });
    });

    await page.getByTestId("file-upload").setInputFiles({
      name: "sample.txt",
      mimeType: "text/plain",
      buffer: Buffer.from("Test content")
    });

    await page.getByRole("button", { name: "Upload" }).click();

    await expect(
      page.getByText("Upload failed")
    ).toBeVisible();
  });
});

```

These are starter UI tests. Update the selectors, API endpoint, allowed formats, 10 MB size assumption, and displayed messages to match your application. The security cases also require backend/API tests; UI assertions alone cannot verify server-side protections.
